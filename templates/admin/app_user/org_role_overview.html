组织角色体系

组织角色体系为 BPMN 工作流引擎提供审批人动态查找能力——引擎根据发起人的组织归属， 自动找到对应的「组长」「部门经理」「基地总经理」来完成审批，无需为每个流程硬编码审批人。

操作步骤

  1. 创建组织架构 先在 子公司/基地、 [L4] 部门、 [L5] 工作组 中建立完整的组织树。
  2. 定义组织角色 进入 [审批] 组织角色， 创建角色（如「组长」scope=工作组、「部门经理」scope=部门）， 建议开启 allow_escalation 避免漏配导致审批中断。
  3. （可选）指派人员到组织单元 步骤②的组织角色详情页已内置 inline 指派表格，可直接在角色页面完成指派。 如需集中管理所有指派，可进入 [审批] 组织角色指派 独立页面。 同一位置可指派多人（正副职），勾选 is_primary 标识主负责人。
  4. （可选）创建审核组 进入 [审批] 审核组， 创建固定审批人池（如「法务审核组」），添加成员。
  5. 关联到工作流节点 进入 app_workflow → WorkflowTaskConfig，配置 BPMN 的 userTask 节点：
    • assignee_type=org_role + 选择 OrgRole 编码 → 动态查找审批人
    • assignee_type=static_group + 选择 ReviewGroup → 固定审批人池
    • assignee_type=static_user + 直接选择用户 → 固定审批人
  6. 验证配置 点击 组织架构总览 矩阵视图， 检查每个角色×组织单元的指派是否完整。

组织角色 (OrgRole)

定义职位角色及其查找作用域。引擎在指定组织层级中查找该角色的负责人。

工作组级 scope=workgroup 在发起人的工作组中查找（如「配方组」的「组长」）
部门级 scope=department 在发起人的部门中查找（如「研发中心」的「部门经理」）
子公司级 scope=subsidiary 在发起人的子公司中查找（如「上海总部」的「基地总经理」）

allow_escalation（逐级回退）：开启后，若当前 scope 找不到指派人， 自动向上一级查找：工作组 → 部门 → 子公司。避免因某个层级漏配而导致审批中断。

组织角色指派 (OrgRoleAssignment)

将具体的用户指派为某个组织角色在特定组织单元中的负责人。

示例：

用户角色组织单元
张三组长配方组（工作组级）
李四部门经理研发中心（部门级）
王五基地总经理上海总部（子公司级）

同一角色在同一组织单元可以有多个指派（如正副职），is_primary 标识主负责人， 引擎优先匹配。

审核组 (ReviewGroup)

静态审批人池——与 OrgRole 的动态查找不同，审核组是一组固定人员。

使用场景：

  • 某些审批节点不需要根据发起人的组织归属动态查找，而是发给固定的几个人
  • 例如「法务审核」→ 法务部的 3 个人组成一个 ReviewGroup
  • 在 WorkflowTaskConfig 中选择 assignee_type=static_group 并关联此审核组

department 字段可限定审核组的部门作用域（留空 = 跨部门通用）。

与工作流引擎的关联

以上配置最终在 app_workflow → WorkflowTaskConfig 中被引用。 每个 BPMN userTask 节点通过 assignee_type 选择解析模式：

assignee_type引用的配置说明
org_role OrgRole.code 动态查找：根据发起人组织归属找到该角色的指派人
static_group ReviewGroup 静态池：固定的一组审批人
static_user 直接指定 User 固定人：写死某个审批人
