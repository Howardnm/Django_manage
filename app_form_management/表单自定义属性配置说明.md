# 表单自定义属性配置说明

## 概述

表单支持通过**自定义属性**标记字段所属的填写步骤，配合 BPMN 审批流程实现**分人分步骤填写**：

- **发起人** — 填写步骤 1，提交后启动审批流程
- **审批人 A** — 填写步骤 2（审批节点绑定的步骤）
- **审批人 B** — 填写步骤 3
- 所有步骤的数据最终合并为完整表单

---

## 一、表单设计器中配置步骤

### 1.1 打开自定义属性面板

在表单设计器中，选中任意字段组件，点击右侧属性区的 **自定义属性配置**（`Custom props`），弹出键值对编辑器。

### 1.2 可用的自定义属性

| 属性名 | 类型 | 必填 | 说明 | 示例 |
|--------|------|------|------|------|
| `step` | `number` | 否 | 步骤号，从 1 开始。未标记的字段默认归入步骤 1 | `1` |
| `stepLabel` | `string` | 否 | 步骤显示名称，用于步骤进度条和提示 | `"基础信息"` |
| `stepDesc` | `string` | 否 | 步骤描述，显示在步骤进度条下方 | `"请填写产品基本信息"` |

### 1.3 配置示例

在自定义属性配置面板中添加 JSON 键值对：

```json
{"step": 1, "stepLabel": "基础信息"}
```

```json
{"step": 2, "stepLabel": "检测结果"}
```

```json
{"step": 3, "stepLabel": "复核确认"}
```

### 1.4 配置后的效果

- **步骤进度条**：表单下方自动显示 `el-steps` 步骤条，标签和步骤号来自上述配置
- **发起人填写页**：只可编辑步骤 1 的字段，其余步骤字段**禁用**且**不要求必填**
- **审批人填写页**：只可编辑自己负责步骤的字段，其余字段只读

---

## 二、BPMN 流程设计器中配置步骤映射

### 2.1 关联步骤号

在 BPMN 流程设计器中，选中 **用户任务（User Task）** 节点，在右侧属性面板的 **Assignment** 分组下：

| 属性 | 说明 | 示例 |
|------|------|------|
| **步骤号** (`formStep`) | 该审批节点负责的表单步骤号，对应表单中 `{"step": N}` 的 N | `2` |
| **步骤标签** (`formStepLabel`) | 该审批节点负责的步骤名称（可选，用于管理端显示） | `"检测结果"` |

### 2.2 配置规则

- 每个用户任务节点的 `formStep` 应与其负责的表单步骤号一致
- 同一个步骤只能由一个用户任务负责（数据合并以 `formStep` 为 key）
- 未配置 `formStep` 的审批节点：审批人可查看全部表单但无需填写特定步骤

## 三、完整工作流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  发起人      │     │  审批人 A    │     │  审批人 B    │
│  填写步骤 1  │ ──→ │  填写步骤 2  │ ──→ │  填写步骤 3  │ ──→ 完成
│              │     │              │     │              │
│  step=1 字段 │     │  step=2 字段 │     │  step=3 字段 │
│  可编辑      │     │  可编辑      │     │  可编辑      │
│  其余禁用    │     │  其余只读    │     │  其余只读    │
└─────────────┘     └─────────────┘     └─────────────┘
```

### 3.1 发起人操作

1. 从创建向导或入口进入表单填写页面
2. 看到完整表单 + 步骤进度条
3. **仅步骤 1 字段可编辑**（其余禁用，灰色）
4. 可保存草稿或提交
5. 提交后自动启动关联的审批流程

### 3.2 审批人操作

1. 进入审批详情页（表单 + 流程图 Tab）
2. 看到蓝色提示条：「您负责填写 **第X步**，该步骤字段已开放填写，其余步骤只读」
3. 填写自己负责步骤的字段
4. 点击 **通过** 时，系统校验当前步骤的必填项
5. 填写的数据自动合并到表单最终数据中

### 3.3 数据合并规则

各步骤填写的数据以 `field` 为 key 合并。后填写的步骤数据会覆盖先填写的同名字段值。

## 四、最佳实践

### 4.1 字段归组建议

- 将同一个业务环节的字段归入同一个步骤
- 例如：步骤 1「基础信息」= 名称、分类、描述；步骤 2「检测结果」= 检测值、是否合格、备注
- 每个步骤建议不超过 10 个字段，保持填写体验清爽

### 4.2 必填项设置

- 只对「当前步骤」设置必填校验（通过设计器常规校验规则配置）
- 非当前步骤的必填校验在运行时自动移除
- 发起人提交时只校验步骤 1 的必填项
- 审批人通过时只校验自己负责步骤的必填项

### 4.3 工作流绑定

- 分步填写必须关联工作流（`template.workflow_id` 不为空），否则所有字段均为可编辑
- 未关联工作流的表单：步骤进度条正常显示，但所有字段均可直接填写

### 4.4 BPMN 与表单步骤一致性

- 确保 BPMN 中用户任务的 `formStep` 值在表单中存在对应的 `{"step": N}` 字段
- 如果一个步骤在表单中无任何字段，步骤进度条中该步骤仍会显示但为空步骤

## 五、常见问题

**Q: 为什么我配置了 step 但看不到步骤进度条？**

A: 步骤进度条仅在存在 2 个以上不同步骤号时显示。检查是否所有字段都标记为同一个 step。

**Q: 为什么审批人可以看到所有字段？**

A: 这是设计如此 —— 审批人可以看到完整表单，便于全面了解信息。只能编辑自己负责步骤的字段。

**Q: 没有配置 step 的字段会怎样？**

A: 默认归入步骤 1。如果所有字段都未配置 step，则表单视为单步表单。

**Q: BPMN 用户任务不配置 formStep 会怎样？**

A: 审批人可以看到全部表单，所有字段只读（除非审批人恰好是步骤 1 的填写人）。

**Q: 同一个字段可以被多个步骤的人修改吗？**

A: 可以。后填写的数据会覆盖先填写的数据。如果需要避免冲突，建议将字段分配到唯一的步骤。
